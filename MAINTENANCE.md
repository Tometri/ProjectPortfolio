# Maintenance Guide

This document explains how the ProjectPortfolio repository is maintained,
automated, and kept consistent.

## What Was Standardized

### Coding Standards

- **`.editorconfig`** enforces consistent indentation, line endings (LF), and
  charset (UTF-8) across all editors and IDEs.
- **`STYLE_GUIDE.md`** documents naming conventions, indentation rules, and
  comment styles for every language used in the repo.
- **`CONTRIBUTING.md`** provides guidelines for contributors.

## How to Run Automation Scripts

### One-Command Maintenance

```bash
# Run everything at once (consistency check + pages update + database init)
make maintenance

# Or with auto-fix for safe issues (trailing whitespace, line endings)
python scripts/run_all_maintenance.py --fix
```

### Individual Scripts

```bash
# Consistency audit — report issues
make lint
# Or: python scripts/check_consistency.py

# Consistency audit — auto-fix safe issues
make fix
# Or: python scripts/check_consistency.py --fix

# Regenerate GitHub Pages files
make update-pages
# Or: python scripts/update_pages.py

# Initialize the database (safe to run multiple times)
make db-init
# Or: python scripts/database.py init
```

### What Each Script Does

| Script | Purpose |
|--------|---------|
| `check_consistency.py` | Checks trailing whitespace, missing newlines, broken Markdown links, spaces in filenames, CRLF line endings, missing READMEs |
| `update_pages.py` | Scans the repo and regenerates `docs/index.md`, `sitemap.xml`, and database exports (`data/labs-certs.md`, `data/labs-certs.json`) |
| `run_all_maintenance.py` | Runs database init + consistency check + pages update in sequence |
| `database.py` | CLI for managing the labs & certifications SQLite database |

## How to Add New Labs & Certifications

### Using the CLI

```bash
# Add a new lab
python scripts/database.py add-lab \
    --name "My New Lab" \
    --description "What the lab covers" \
    --repo-path "labs/my-new-lab/" \
    --start-date "2026-04-01" \
    --status in_progress \
    --difficulty intermediate

# Mark a lab as completed
python scripts/database.py update-lab --id 1 --status completed --completion-date "2026-04-15"

# Add a new certification
python scripts/database.py add-cert \
    --name "AWS Cloud Practitioner" \
    --issuer "Amazon Web Services" \
    --issue-date "2026-05-01" \
    --credential-id "AWS-CCP-12345"

# View all entries
python scripts/database.py list-labs
python scripts/database.py list-certs

# Export to Markdown or JSON
python scripts/database.py export-md
python scripts/database.py export-json
```

### Database Details

- **Location**: `data/labs-certs.db` (SQLite, gitignored — regenerated by `init`)
- **Tables**: `labs` and `certifications`
- **Exports**: `data/labs-certs.md` and `data/labs-certs.json` (committed to repo)
- **Schema**: Defined in `scripts/database.py` with auto-updating timestamps

## How the Pages Site Stays Up-to-Date

### Automatic (GitHub Actions)

The `.github/workflows/maintenance.yml` workflow runs:
- **On schedule**: Every Monday at 06:00 UTC
- **On push**: When content files change on `main`
- **Manually**: From the GitHub Actions tab (workflow_dispatch)

The workflow:
1. Runs `check_consistency.py --fix` to clean up formatting
2. Runs `database.py init` to ensure the database exists
3. Runs `update_pages.py` to regenerate pages files
4. Commits and pushes any changes automatically

### Manual

After adding new content:

```bash
# 1. Add your files to the appropriate directory
# 2. (Optional) Add database entries for labs/certs
python scripts/database.py add-lab --name "..." ...

# 3. Run maintenance to update everything
make maintenance

# 4. Commit and push
git add -A
git commit -m "Add new content"
git push
```

## Future Expansion

The `config/settings.example.env` file includes placeholder settings for
future integrations:
- **Notion sync** — automatically sync labs/certs with a Notion database
- **LinkedIn sync** — pull certification data from LinkedIn
- **GitHub API** — auto-detect new repos and labs

To set up: copy `config/settings.example.env` to `config/settings.env` and
fill in your API keys.
